# Дверь — постоянный адрес локального чата

Здесь лежит **только страница входа**. Сам чат, модели и диалоги — на домашнем ПК,
эта страница всего лишь даёт постоянный адрес и пускает проверенных людей.

- `index.html` — дверь: форма «имя + пароль», при успехе переходит на текущий адрес туннеля.
- `status.json` — адрес туннеля. Его перезаписывает окно «2. Сервер» через GitHub API при каждом запуске.

## Как это работает

1. Страница читает `status.json` и узнаёт, где сейчас сервер.
2. Введённые имя и пароль уходят по HTTPS прямо на домашний ПК (`/__door/auth`).
3. Пароль проверяется на ПК (PBKDF2-SHA256, 150 000 итераций). Сюда он не попадает и не сохраняется.
4. ПК отдаёт одноразовый билет на 120 секунд, страница переходит по нему на туннель и получает cookie.

Быстрый вход: после первого входа в `localStorage` этого браузера остаётся случайный ключ
(не пароль). Дверь сама меняет его на новый билет, поэтому пароль спрашивается только
на новых устройствах. «Забыть это устройство» стирает ключ.

## Если туннель сменил адрес

Страница чата сама уходит сюда с пометками `?r=tunnel&u=<новый адрес>`: `r=tunnel` — «связь
пропала», `u` — адрес, который чат только что вычитал из `status.json`. Дверь проверяет
подсказку первой (не тратит время на мёртвый адрес из памяти), а если связи нет — пишет
об этом вместо сухого «не удалось войти».

Перезагрузка страницы чата при мёртвом туннеле тоже приводит сюда: service worker `sw.js` на
стороне чата перехватывает переход и перенаправляет на дверь с `?r=tunnel`.

## Если сервер выключен

Страница честно пишет «сервер не отвечает» — включите ПК и окно «2. Сервер».
Кнопка «Войти» в это время бесполезна: авторизация живёт только на ПК.

Публичный репозиторий нужен GitHub Pages, поэтому адрес туннеля виден всем.
Войти по нему без пароля нельзя — проверка доступа выполняется на сервере.
