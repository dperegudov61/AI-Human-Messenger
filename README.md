# AI and Human Messenger — страница чата и админка

Репозиторий: `dperegudov61/AI-Human-Messenger`
Чат: **https://dperegudov61.github.io/AI-Human-Messenger/**
Админка: **https://dperegudov61.github.io/AI-Human-Messenger/admin.html**

Это постоянный адрес: адрес туннеля меняется при каждом перезапуске, а страницы — нет,
они сами находят живой мост и работают с ним.

| файл | что это |
|---|---|
| `index.html` | страница чата: ИИ-чаты, люди, сообщения, картинки |
| `admin.html` | админка: система (журналы, команды) и люди |
| `theme.js` | тема (тёмная / светлая / как в системе) и язык: `data-theme`, переключатель, `GET|POST /__prefs`. Тот же файл лежит в `site\` — держать одинаковыми (`docs\THEME.md`) |
| `404.html` | копия `index.html`: Pages отдаёт её на любой неизвестный путь (кладёт `publish_door.ps1`) |
| `.nojekyll` | отключает обработку Jekyll |

Публикация: правим `messenger\` в проекте → `.\publish_door.ps1` → через полминуты
страницы обновятся.

## Страница чата

1. **Мост.** Читает `status.json` репозитория `dperegudov61.github.io` (api.github.com →
   Pages → raw), проверяет кандидатов `GET /__door/hi`, свежие — первыми, старше 60 минут —
   в хвост. Последний живой адрес помнит в `localStorage`.
2. **Вход.** Токен лежит в `door.token` — его кладёт `/accounts/` (страницы одного сайта
   видят общий `localStorage`). Если токена нет, но сохранён быстрый ключ (`door.key`),
   страница меняет его на токен через `POST /__door/auth`. Ссылка из админки приходит как
   `?tk=<ключ>` — это тот же быстрый ключ (кладётся в `door.key`), а не сеанс.
   При обрыве связи ключ **не стирается**: страница ищет новый мост и пробует ещё раз.
   Без входа — оверлей «Войти».
3. **Запросы.** Абсолютный адрес моста + `Authorization: Bearer <токен>`.
   Картинки — `/f/<id>?v=small&tk=<токен>` (у `<img>` нет заголовков).
4. **Левое меню — два выпадающих списка:** «ИИ чаты» и «Люди». Состояние (свёрнут/развёрнут)
   запоминается. «＋» в заголовке создаёт: у ИИ — чат с выбранной моделью и пресетом,
   у людей — личную переписку с выбранным человеком. «✕» у строки — удалить (файл уезжает
   в `data\trash` на сервере).
5. **Люди.** `GET /__people` — кто есть и кто на связи; `POST /__pm/open` — личная переписка
   (один файл на двоих, третий не видит). Общий чат — первым в списке «Люди».
6. **Сообщения.** Людям — `POST /__msg {id, text, cid, mid}` (ключ `cid` — чтобы повтор
   после обрыва не задвоил запись; `mid` — id сообщения, придуманный страницей, чтобы
   запись в кэше и на сервере была одним объектом). ИИ — `POST /v1/chat/completions`
   (заголовок `X-Chat-Id`), затем `POST /__log`.
6.1. **Новое без перезагрузки.** Страница держит длинный опрос `POST /__events`
   (висит до 25 с, отвечает сразу, как только что-то случилось). Событие `msg` несёт
   само сообщение (или только `mid` для длинного), `del` — id удалённых. Номер последнего
   события лежит в `ch.seq`. В простое это ~356 байт за 25 с вместо полной перекачки
   диалога каждые 6 с. При обрыве — повторы 0,8→15 с, поиск нового моста, после
   перезапуска сервера — сверка по `reset`. Подробно: `docs\CHANNEL.md`.
6.2. **Кэш переписки.** При входе список чатов и открытый чат рисуются сразу из
   IndexedDB (`msgcache`), затем `POST /__sync` отправляет список id сообщений и файлов,
   а сервер отвечает своими: чего у клиента нет — приходит содержимым, чего нет на
   сервере — превращается в «сообщение удалено». Список чатов — `POST /__chats/sync`;
   удалённый чат уносит свои сообщения. Долгое нажатие на своё сообщение — `POST /__msg/delete`
   (soft-delete). Файлы собираются в `chunks` по 256 КБ и докачиваются `Range`.
   Даты `mt/at` используются для чистки. Подробно: `docs\CACHE.md`.
7. **Файлы.** «＋» в строке ввода — загрузка. Сначала считается sha256 в браузере и
   спрашивается `POST /__file/check`: если такой файл уже есть — ничего не грузится,
   страница зовёт `POST /__file/link` и показывает готовый. Иначе —`POST /__file/upload`
   через XHR с процентом загрузки. В ленте — `view\<id>.jpg` (progressive JPEG, рисуется
   по мере прихода), клик — оригинал, «⬇» — скачать оригинал с изначальным именем
   (`?raw=1&dl=1`), «🔗» — ключ-ссылка (`POST /__img/share`). Чужие файлы сервер не отдаёт.
   Подробно: `docs\FILES.md`.
8. **Настройки бота (⚙)** — для чата с моделью картинок: три пресета, ползунки ширины и
   высоты 144–720 (связаны: тянете одну сторону — вторая держит соотношение, кадр не станет
   уже 1:4), шаги 4–24. Сохранение показывает «сохранено ✓» или текст ошибки.
9. **«От имени».** Если админ работает от чужого имени, внизу слева ник вида
   «Сергей (Дима Администратор)», сверху — жёлтая полоса с кнопкой «вернуться к себе».

## Админка

Лежит в открытом репозитории — это нормально: защита серверная. Без сессии админа
`/__adm/*` отвечают 403, и страница получает пустоту. Кнопка «Админка» появляется на
главной странице только после входа администратором.

* **Система** — журналы из `logs\*.log` (хвост, автообновление 5 с) и команды серверу:
  остановить генерации, перезапустить сервер, остановить сервер, выключить ПК (60 с),
  отменить выключение. Все, кроме отмены, требуют капчу: сервер отдаёт картинку с четырьмя
  цифрами (`GET /__adm/cap`), ответ живёт 3 минуты и срабатывает один раз.
  Произвольных команд оболочки нет — только белый список.
* **Люди** — сначала карточка «Новая учётная запись» (имя, тип, пароль; пустой пароль —
  сервер выдаст случайный и покажет один раз). Ниже список с id (8 цифр), онлайн-точкой
  и временем последнего входа. Карточка человека: переименовать (диалоги и картинки
  переносятся вместе с человеком, сеансы не рвутся), задать пароль (пусто — сервер выдаст
  случайный; все сеансы закрываются), сменить роль, выпустить ссылку-вход с QR
  (новая ссылка гасит прежние), выкинуть со всех устройств, зайти от имени.
